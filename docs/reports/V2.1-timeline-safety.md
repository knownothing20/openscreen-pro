## 3. 原有功能与新增功能的区别

- **多选本身不是新功能**：F2.7 已经实现了 Shift 点击加选、多选高亮与批量删除。
  本轮**没有重做**，只做了三件它之前没有的事：Ctrl/Cmd 同义、整块拖动、批量属性粘贴。
- **拖动原本只能一 pill 一 pill 地拖**，即使选中了三个。现在抓住其中任意一个都会带走整块。
- **`Ctrl+Shift+V` 原本只作用于"最后点击的那个"**，即使面板上亮着三个。现在作用于整块。
- **导出原本直接写用户选定的路径**。现在写同目录临时文件，成功后才 rename 覆盖。

## 6. 导出覆盖保护与失败注入

### 规则（`electron/exportPathGuard.ts`）

1. 目标必须是绝对路径，且扩展名为 `.mp4` / `.gif`（工程文件因此天然不可作为目标）。
2. 目标不得等于本次导出正在读取的任一源文件（`screenPath` / `webcamPath`，大小写不敏感）。
   这份名单从**本次导出的 clips 里读**，不是由渲染进程另外传一份可以写错的清单。
3. 编码写入 `<目标名>.partial-<token>.<扩展名>`，**与目标同目录**（rename 不能跨卷，且这一步就该是 rename）。
4. 成功后 `fs.rename` 提交；失败或取消则删除临时文件，**原文件一个字节都不动**。

### 单元/失败注入测试（13 条，`electron/exportPathGuard.test.ts`）

覆盖：非绝对路径拒绝、错误扩展名拒绝、覆盖源视频拒绝、覆盖摄像头源拒绝、大小写绕过拒绝、
新名字放行、临时文件位置与扩展名、提交替换旧文件、**写入失败后旧文件完好且无临时残留**、
临时文件已不存在时清理不抛错、目标原本不存在时正常创建。

### 真实导出（走真实 app + 原生合成器，非 mock）

```
openscreen export b21_multiselect.openscreen --out b21-v21/b21-export.mp4 --json
→ {"event":"done","success":true,"outputPath":"...b21-export.mp4","width":1598,"height":1080}
```

产物：**77,755,356 B**，h264 **1598×1080 / 2554 帧 / 42.566s**，含 AAC（1997 帧）。
导出目录与工程目录内**没有任何 `*.partial-*` 残留**。

### 拒绝覆盖源文件的真实注入

把源录屏**复制**一份（`guard/recording-copy.mp4`，29,615,896 B），让工程指向这份副本，然后
把导出目标设成副本本身：

```
{"event":"error","message":"NativeBridgeRequestError: That path is a source file this export is
 reading from. Pick another name — overwriting it would destroy the footage the project needs."}
{"event":"done","success":false,...}
```

拒绝之后：副本 SHA256 仍是 `858cf41bcedccbd0968b0cc4…`（与尝试前一致），体积不变，
目录里没有临时文件。**没有动真实录屏**，只用副本做了注入。

编码器、分辨率、音频与 NVENC 路径**未改动**（只是换了写入路径）。

## 7. 媒体复用与 Seek 验证

**结论：已完整，未改代码。**

- **同一素材跨多个 clip 不重复初始化**：`crates/compositor/src/pipeline_windows.rs:1651-1656`
  以路径为 key 建 `screen_decs` / `webcam_decs` 两个 `HashMap`，注释写明"每个路径只打开一次，
  跨 clip 复用"，后续逐 clip 只取用（`:1731`）。
- **素材副本复用**：`src/lib/exporter/localSourceFile.ts:60-94` —— OPFS 副本按 cache 名做引用
  计数，同一份并发调用会 join 同一个 in-flight copy，释放只减计数；剪枝永不删除仍有引用的条目。
  这同时保证了"项目关闭/媒体替换时不误删正在被读的副本"。
- **视觉属性修改不触发媒体重新准备**：`src/components/ai-edition/VirtualPreview.tsx:1639` 的
  `<video>` 以 `activeSource.id` 为 key —— 改 target/timing 不会 remount，只有换素材才会。
- **快速 Seek 的旧帧保护**：`VirtualPreview.tsx:544-1534` 用 `pendingSeekRef` 维持"单飞 + 最新
  目标胜出"，`seekTarget.requestId` 每次请求递增。已有测试
  `src/components/ai-edition/VirtualPreview.seekStorm.test.tsx` 直接断言："不把新 seek 叠到仍在
  seek 的元素上"、"demuxer 空闲后应用**最新**目标而不是排队中的旧目标"、"播放头停下后不再 seek"。

因此本轮没有新增全局缓存，也没有改动解码器生命周期。

## 12. 下一版本（V2.2）建议

1. **给 pill 加稳定的 `data-pill-id` / `data-pill-kind`**：本轮验收不得不靠 `title` 与哈希类名
   定位元素，绕开了缩放手柄；有数据属性后 e2e 会稳得多。
2. **整块拖动的键盘版本**：选中多段后用方向键整体微调，比鼠标更精确。
3. **导出体验**：现在拒绝覆盖时给的是原生错误串；可以在对话框阶段就做一次校验，把"这是源
   文件"提前到用户选路径时提示，而不是等编码前才失败。
4. **`write-export-to-path` 的源文件保护**：目前那条路径（CLI 混音回写）只做了原子写入，
   没有源文件名单可用；要补的话需要把受保护路径随调用一起传。
5. **安装包验收**：V2.1 的改动要体现在 NSIS 包里，需要在重新出包后补一次安装态闭环。
