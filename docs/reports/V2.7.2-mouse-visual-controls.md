## 2. CursorPane 判定的真实根因（含一处自我更正）

读链路：`FloatingInspector` → `useHasRecordedCursor()` → `stateChangesOf(path)` →
`cursorStateChanges(data.samples).length > 0`。

`cursorStateChanges` 里 `const type = cursorType || "arrow"`，所以**122 条 `cursorType: null` 的样本会产出
1 条 `{0, "arrow"}`，length 是 1，不是 0**。也就是说：单看这个函数，`hasCursor` 本该是 `true`。

所以上一轮我写的"sidecar 全 null → 0 条变化 → 面板隐藏"**不成立**，本轮更正。真实原因在更上游：
`clipSourceRanges(document)` 是否返回了路径、`getRecordingData` 是否抛错（`catch` 会吞掉并把该 path
从缓存里删掉，于是 `cursorDataIn` 永远拿不到答案、返回 `null`，面板按 `=== true` 隐藏）。
这条链本轮**没能验证到底**（§5）。

即便如此，原来的判定确实是错的——它把"能不能命名光标形状"当成了"有没有可画的东西"。修复见 §3。

## 3. 修改内容（最小改动，不重写面板）

`src/components/ai-edition/recordedCursorTypes.ts`：

- 新增 `cursorCapabilitiesOf(samples) → { position, clicks, shapes }`，三个独立答案。
  `position` 要求时间戳有限非负、`cx/cy` 有限且在 `0..1`（合成器能真正落点）；`clicks` 认
  `click / double-click / right-click / middle-click`；`shapes` 认非空 `cursorType`。
- `hasCursorByPath`（布尔）换成 `capabilitiesByPath`，在 `stateChangesOf` 里一次填好。
- `cursorDataIn` 的判据从"状态变化数 > 0"改成 **`position || shapes`**：有可落点的位置就能画指针、
  波纹、轨迹、光圈、调大小；只有形状选择器需要 `shapes`，它自己读 `capabilitiesByPath`。

未改 `CursorPane`、WGC、`cursor-sampler`、sidecar v3 格式、原生合成器。

面板里依赖形状的那段（`useRecordedCursorTypes` → `recordedKinds`）本来就是空集合优雅降级，
`shapes=false` 时只是不给形状配图，不需要额外禁用。

## 5. 真实 Electron：通道在，验证没做完

前一轮证明的路径仍可用：`_electron.launch` → HUD → `switchToEditor()` → 编辑器 → `Ctrl+O` → 工程。

本轮实测结果：

```
PROJECTS []                                  ← 打开对话框出现了，但列表是空的
FAIL locator.click: waiting for /^V2\.7\.2 GUI acceptance/
```

工程文件确实在磁盘上（`%APPDATA%\openscreen\projects\` 下多个 `.openscreen` 可正常解析），所以问题在
"列表还没加载完就被读取"或"dev-server 模式下列表接口没就绪"——**没有排查到底**，因为要先把 B 收口，
而这条链前面已经耗掉太多时间。

同时确认一件对交付有影响的事：**`npx vite build --emptyOutDir false` 不重建 renderer**
（27 ms、只输出 preload、chunk 哈希不变），所以前几轮"重建 dist 后跑真 Electron"读到的很可能一直是旧前端。
这也解释了为什么真窗口里看不到任何前端修复。`npx vite build`（默认清空）会被 safe-delete 守卫拦在
`dist/cursors` 上；用 `--outDir dist-check` 验证过**构建链本身正常**（产出新哈希 chunk），
但该目录已删除，`dist` 与打包版仍是旧前端。

## 6. 任务的 B：7/7 与 2/2

`tests/e2e/v4-shell.spec.ts` 第七条的真实规则（实测，不是推断）：

```
BASE      1.5×/1.8×/2.2×   aria-pressed 在 1.8×
AFTER_22  1.5×/1.8×/2.2×   aria-pressed 在 2.2×      ← 行不变，只有选中态移动
```

即：**三档固定 + 选中态**，不是滑窗。上一轮我按"滑窗"改写是错的，本轮改回：

- `toHaveCount(4)` → `toHaveText(["1.5×","1.8×","2.2×"])`（注明六档塞不进 300 px）；
- 提交后补 `toHaveAttribute("aria-pressed","true")`，验证"点击档位真的改了设置"；
- 自定义 2.50× 的药丸**收窄到时间轴作用域**再断言，因为同一倍率在轨与概览条各画一次，
  文档级文本匹配会数到 2 个——原来的 1 个期望才是错的。

结果：**v4-shell 7/7 + cursor-pane 2/2 = 9 passed**。
