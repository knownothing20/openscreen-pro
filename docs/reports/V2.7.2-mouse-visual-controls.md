## 2. AMD 失败调查：是测试入口用错，不是产品缺陷

**上轮的错**：用了 `OPENSCREEN_EXPORT_ENCODER=h264_amf`。这个环境变量是"**按名字强制某个候选**"的
测试钩子（`pipeline_windows.rs:1713`），不是设备选择机制；它在候选列表里找不到该名字时直接报
`ne nomme aucun candidat de ce codec`。

**正式机制**（`electron/app-settings.ts:96`、`src/lib/encoderDevices.ts:298`）：

```
recording-settings.json  lastEncoder.device = "id:<PnP 设备实例 ID>"
        → resolveEncoderDevice() 解析成 adapter LUID
        → exportMulti({ encoderDevice: <LUID> })
        → D3D11 设备建在该 adapter 上 → 候选表按 vendor 过滤
```

本机 PnP（`Get-CimInstance Win32_VideoController`）：

| 卡 | PNPDeviceID |
|---|---|
| NVIDIA RTX 4070 Ti SUPER | `PCI\VEN_10DE&DEV_2705&SUBSYS_413C1458&REV_A1\4&25C6DA53&0&0009` |
| AMD Radeon 780M | `PCI\VEN_1002&DEV_1900&SUBSYS_01241002&REV_BA\4&98C338A&0&0041` |

把 `lastEncoder.device` 写成 `id:<AMD 那串>`、`codec=h264`，再跑同一条导出命令：

```
[pipeline] encodeur vidéo : h264_amf (textures D3D11, zéro-copie)
```

**产品代码一行没改。** `candidates()`、GPU 优先级、编码器安全检查都原样。

## 4. 真实 CursorPane 操作 —— BLOCKED，阻塞点有两处

这一轮按任务要求去恢复了既有 GUI 自动化，结果如下。

**4.1 既有 e2e 设施当前是全红的。** `tests/e2e/v4-shell.spec.ts` 7 条测试在 dev server 上跑，
**7 条全部失败**，失败点都一样：`locator('[data-clip-id]')` 解析到 0 个元素。
原因不是选择器写错，而是产品改了行为——`NewEditorShell.tsx:383-390` 的注释写得很清楚：

> "Nothing else happens on mount. This used to fall back to opening the most recent project…
> The empty state already offers Load Project, record and import, so the choice is theirs."

`seedAndOpen()` 依赖"启动自动加载最近工程"，这条路径已经不存在了，所以 spec 需要改成
`Ctrl+O → 列表里选 → 进编辑器`。

**4.2 按新路径能进编辑器，但 Cursor 面板不出现。** 按真实用户操作重写脚本：seed 工程 →
`Ctrl+O` → 弹窗出现（"Open project / Pick up an existing project… / V2.7.2 GUI fixture"）→ 选中 →
编辑器渲染（`Rename project`、`Collapse inspector`、时间轴工具条都在）。但右侧 facet 只有
Composition / Camera layout / Audio / Transcript，**没有 Cursor**。

原因在 `FloatingInspector.tsx:154`：

```ts
const hasCursor = useHasRecordedCursor() === true;
const facets = hasCursor ? FACETS : FACETS.filter(({ id }) => id !== "cursor");
```

`useHasRecordedCursor()` 要读真实 cursor sidecar（`nativeBridgeClient.cursor.getRecordingData`），
而 **`browserShim` 根本没有 `cursor` domain**（`grep "cursor:" src/native/browserShim.ts` 零命中）。
所以浏览器模式下这个面板永远不渲染，与操作无关。

**4.3 真 Electron 路径的硬约束。** 按 AGENTS.md 自己的描述，HUD 是 click-through
（`setIgnoreMouseEvents(true)`），只有**真实 OS 鼠标移动**才能命中它的控件；Playwright 注入的
click 落在 OS hit-test 之下，"看起来成功了，而 click-through 从未被走通"。本会话没有
computer-use MCP，也就没有真实鼠标事件源。这不是"懒得跑"，是这条路在本环境下物理不可达。

**因此 B 项未闭环**：GUI 里改设置 → Ctrl+S → 关进程 → 新进程重开 → 逐字段核对，一条都没跑成。
已有的替代证据是数据层的（`legacyEditor` 往返、`normalizeProjectEditor` 白名单契约、场景下发），
它们能证明"存下来的东西是对的"，但证明不了"用户在窗口里点的那一下"。这两件事不能互相顶替。
