## 2. 旧 E2E 七条失败的根因与修复

**根因有两个，不是一个。**

1. `seedAndOpen()` 假设"启动自动打开最近工程"。产品已改为主动选择——`NewEditorShell.tsx:383` 的注释写着：
   *"This used to fall back to opening the most recent project, which dropped the user into a project they
   had not chosen."* 所以不是测试跑慢了，是那条路径不存在了。
2. 第 7 条（zoom level row）另有原因：档位行从**固定 4 档**改成**滑窗 3 档**（当前档 + 左右邻居），
   `toHaveCount(4)` 与后续 `nth()` 索引整体失效。实测深度 3 时是 `1.5× / 1.8× / 2.2×`。

**修复**（`tests/e2e/v4-shell.spec.ts`）

```ts
// 新流程：seed → 启动 → Ctrl+O（重试到弹窗真的出现）→ 按标题精确选择 → 等 clip
await expect(async () => {
  await page.keyboard.press("Control+o");
  await expect(picker).toBeVisible({ timeout: 1_500 });
}).toPass({ timeout: 15_000 });
await picker.getByRole("button", { name: new RegExp(`^${escapeForRegExp(title)}`) }).click();
```

- 不依赖固定 sleep：快捷键监听要等 shell 挂载后才生效，`toPass` 重试比猜时长可靠；
- 按标题**精确**匹配，避免打开前缀相同的别的工程；
- 产品启动逻辑一行未改。

**结果：6/7 通过。** 第 7 条把 `toHaveCount(4)` 改成实测的 `["1.5×","1.8×","2.2×"]` 之后，又卡在
`zoomPill("2.50×")` 期望 1 个、实际 2 个——那是另一处产品演进（自定义档同时出现在轨道与药丸两层）。
继续改等于重写这条测试的整条断言链，**不在本轮授权内硬改**，如实留红。

## 3. browserShim 的 Cursor 测试接口

`FloatingInspector.tsx:154` 用 `useHasRecordedCursor()` 决定是否显示 Cursor facet，该判断读
`nativeBridgeClient.cursor.getRecordingData(path)` → `cursorStateChanges(samples)` → `length > 0`。
浏览器模式没有这个 domain，面板于是永远不出现。

按真实契约（`src/native/contracts.ts` 的 `CursorRecordingData` / `CursorCapabilities`）补最小实现：

- `getCapabilities` / `getRecordingData(videoPath?)` / `getTelemetry(videoPath?)`，都返回 Promise；
- 数据来自 `localStorage["browser-shim-cursor-v1"]`，按视频路径取，缺省回落 `default`；
- **没有 fixture 时不编造**：返回 `null`，等价于"系统光标烧进画面、没有 sidecar"的录制；
- fixture 损坏按"无数据"处理，不抛；
- 未触碰真实 Windows native bridge。

验证：`src/native/browserShim.cursor.test.ts`（3 条，全绿）——无 fixture 返回 null / 有 fixture 按路径与
default 命中、telemetry 只返回 samples / 坏 JSON 不抛。

## 5. 真实 Electron 测试结果

上一轮"物理不可达"的判断被推翻——通道存在，只是入口不是鼠标：

```
_electron.launch({ args: ["."] })      → HUD 窗口 (windowType=hud-overlay)
window.electronAPI.switchToEditor()    → 编辑器窗口 (windowType=editor)
Ctrl+O → 选工程                         → 时间线出现 (CLIPS = 1)
```

- 与真实用户入口的差别：**用 HUD 的 `switchToEditor` IPC 代替"点击 HUD 上的 Open Studio"**。HUD 按钮调的
  就是这个 IPC，区别只在触发方式。没有关闭 click-through 来迁就测试。
- `ELECTRON_RUN_AS_NODE` 在启动环境里被显式删除。
- 必须先清残留 `electron.exe`：单实例锁按 userData 生效，残留进程会让新实例静默退出（表现为 "target closed"）。
  脚本里做了启动重试，并把这条写进注释。

**真实窗口里读到的**：工程标题、`已保存` 状态、时间线 1 个 clip、画面合成面板（背景/画框/样式/运动/开场）
全部正常渲染，无白屏、无 React 异常。

**卡住的地方**：Cursor facet 仍不出现。根因查到了：

```
native cursor.getRecordingData("…\still.mp4")
→ { ok: true, data: { version: 3, samples: [ … 122 条 … ] } }
```

**原生读取是成功的**，但这份 sidecar 每个 sample 都是 `cursorType: null`。`cursorStateChanges()` 要靠
cursorType 才能命名"状态变化"，全 null 就得 0 条 → `hasCursor = false` → 面板隐藏。

这是**设计行为**：没有可命名的光标状态，面板上每个控件都改不了任何东西，编辑器就把它藏起来。
要让它出现只能塞一份带 cursorType 的 sidecar——那属于"把模拟数据塞进真实 Electron 充当验收"，
任务明确禁止。**所以停在这里，不做假。**

## 15. 能否关闭 V2.7.2

**不能。** 缺的是同一条链上的三环：真实窗口里操作 CursorPane → 保存 → 新进程重开（外加 600 秒 GUI Seek）。

下一轮最小路径二选一：

1. **用一份带 `cursorType` 的真实 sidecar**（真机录一段有 hover/点击、光标形状变化过的短片），面板就会在
   真实 Electron 里出现——不需要伪造数据，也不需要改产品代码；
2. 或者让 `hasCursor` 的判据不再要求 cursorType（若产品认为"有 sidecar"就够）——那是产品决策，不是测试问题。

两条都不在本轮授权内（一条要新录制，一条要改产品行为），所以停在这里。
