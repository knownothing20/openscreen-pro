## 2. 旧 Renderer 为什么"没更新"——上一轮判断错了

上一轮我写"`vite build --emptyOutDir false` 不重建 renderer，27 ms 只输出 preload"。**这是错的。**

完整日志（不 `tail`）：

```
✓ 2326 modules transformed.
✓ built in 30.93s          ← renderer
✓ 2476 modules transformed.
✓ built in 22.78s          ← main
✓ 2 modules transformed.
dist-electron/preload.mjs  13.20 kB
✓ built in 27ms            ← preload
```

我用 `tail -3` 只看到最后三行——那是 preload 的 27 ms，被我当成了"整个构建 27 ms 就结束"。

`dist/index.html` 的 md5 没变也不是"没更新"：它只引用入口 chunk，入口里那张
`import("./AiEditionShell-<hash>.js")` 表恰好没变，真正变化的是被引用的分块。当前链路：

```
dist/index.html → assets/index-DdW_1XRL.js → AiEditionShell-D2bw90Qy.js   (18:02:39 生成)
```

**真正的问题在别处**：`--emptyOutDir false` **不删除历史 chunk**。`dist/assets` 里堆着 7 个
`Modals-*.js`、6 个 `AiEditionShell-*.js`；我注入诊断探针那一次产生的 `Modals-DVVvERJM.js`
就留在里面，并被 `v272-final2` 打进了 asar。已单独删掉该文件、重打包为 `v272-final3`，
并在 asar 里 `grep -c "__cursorProbe"` 确认为 **0**。

## 3. CursorPane 为什么"不出现"——也是我的查找错误

上一轮把"面板不出现"写成 gating 缺陷并判 BLOCKED。本轮用运行时探针把链路每一层的值打出来：

```
PROBE {
  paths:    ["C:/Users/leon/AppData/Local/Temp/os-v272/still.mp4"],
  caps:     [{ "position": true, "clicks": true, "shapes": false }],
  drawable: [true]
}
```

判定链**一直是正确的**。面板不出现的真正原因：**我在找 `aria-label="Cursor"`，而这台机器上的
应用是中文界面，标签是"光标"**。

```
ALL_LABELS ["光标"]
CURSOR_FACET 1
PANEL ["聊天面板","OpenScreen","重命名项目",…,"点击按压","点击波纹","左键","右键","中键",
       "圆点","圆环","鼠标轨迹","光标光圈",…]
```

同样的错误没有发生在 `tests/e2e/*`，因为浏览器测试跑的是英文 locale。

所以：`c6e1823` 的 capability 拆分（`position` / `clicks` / `shapes` 三问分离，`hasCursor` 判据
从"状态变化数 > 0"改为 `position || shapes`）在语义上是对的、有 7 条测试锁着，**但它不是这个
现象的原因**。这点必须写清楚，否则会被读成"修好了"。

## 7. 600 秒 Sidecar GUI Seek

工程 `proj_v272_10m` 引用 `recording-1794219250006.mp4`（873 MB，sidecar 3.79 MB / 17 809 samples）。

| 请求 | 实际播放头 | 响应 | renderer 堆 | main RSS |
|---|---|---|---|---|
| 打开工程 | — | **326 ms** | 18 MB | 491 MB |
| 0 s | 0 | 70 ms | 18 | 491 |
| 60 s | 51.745 | 53 ms | 18 | 598 |
| 300 s | 300 | 55 ms | 18 | 593 |
| 590 s | 599.974 | 52 ms | 18 | 591 |
| 120 s | 113.809 | 46 ms | 18 | 596 |
| 599 s | 600 | 66 ms | 18 | 592 |
| 0 s（回） | 0 | 50 ms | 18 | 585 |
| 300 s 重复 | 300 = 300 | — | — | — |
| 60 s 逆向复访 | 51.745（与首次完全相同） | 51 ms | — | — |

读法：
- **无漂移**：同一请求两次落在同一时间（300=300），60 s 正向与逆向复访都是 51.745。
- 请求值与落点有固定偏差（60→51.7、120→113.8），那是**点击坐标到时间的映射误差**（时间轴含 padding），
  不是 seek 失准——同一请求永远落在同一处，映射是确定的。
- 内存：renderer 堆稳定 18 MB（3.79 MB sidecar 解析后）；main 由 491 → 594 MB，是视频解码缓冲，
  之后在 585–598 波动，无持续增长。
- 该素材 **0 个点击事件**，只能证明长侧车的位置/时间定位，不能证明 10 分钟后的点击动画。

不是未通过的检查——但按"全部完成才叫 COMPLETE"的字面标准，它算一项没做。
