## 2. 本轮真正新增的

面板里每条建议一行：勾选框 + 时间按钮（`5.0s – 8.7s`）。下面四个按钮：全选 / 全不选 /
`Apply {count}` / Discard。

- 勾选状态与 `autoZooms` **平行存放**，每次重新分析都会重置为全选——一条过期的勾选不可能落到
  它没针对的那份计划上；
- `Apply {count}` 直接显示当前选中数，取消勾选会立刻变成 `Apply 0`（此时点击不写任何东西）；
- 点时间按钮调 `useProjectStore.getState().setCurrentTime(start / 1000)`，**只动播放头**。

批量写入仍是上一轮那一次：
`setDocument(next, { history: false })` → `saveDocument(next, { history: true, historyBase: previous })`。
选中几条都只有一次写入，所以仍是一条 Ctrl+Z。

## 3. 真机数据

素材 `recording-1794219210593.mp4`（15.02 s），sidecar 里 2 次点击。

```
ZOOMS_0            0
ROWS               1   checked true
JUMP               5.0s – 8.7s → playhead 4.966   (expected 5)
ZOOMS_AFTER_PREVIEW 0      ← 预览没有写工程
AFTER_UNCHECK      Apply 0
AFTER_SELECT_ALL   Apply 1
ZOOMS_AFTER_APPLY  1
```

跳转落点 4.966 而请求是 5.0：这是 seek 落在一帧内（15 s / 902 帧 ≈ 16.7 ms，实测差 34 ms），
不是映射错误。

## 4. 为什么"多条批量 Undo"仍然是 NOT_RUN

任务书允许用构造数据做确定性单测，但**真机批量验收需要至少 3 条建议**，而这台机器上唯一有点击
素材只有 2 次点击，规划器把它们合并成 1 条。

我可以伪造 sidecar 造出 3 条，但那是"用手写 JSON 冒充真实录制"——任务书明确禁止。也可以故意
关掉规划器的合并规则去凑数量，那等于破坏产品行为来让测试好看。

所以这一项如实标 NOT_RUN，机制上它是成立的（一次写入 = 一条历史，已有 1 条的真机证据），
但"3 条一起撤"没有实测。要补，需要一段真实的多区域操作录屏。

**一个必须记下来的坑**：Windows 上 Python 的 `write_text` 默认把 `\n` 翻成 `\r\n`，所以我批量
改 locale 文件时每个文件都被写成 CRLF，`git diff --check` 把它们全报成 trailing whitespace。
写文件要么 `newline="\n"`，要么事后按字节把 `\r\n` 换回 `\n`。本轮是后者。

新增 4 个 i18n 键，仍然只有 `en` 是原文，其余 14 个 locale 是英文占位——**键齐全不等于翻译完成**。
