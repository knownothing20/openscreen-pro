## 2. 泄漏是怎么堵的

上一轮的预览只存了区域，没存"这些区域是对哪份片子算的"。切换工程、Trim、Split、重排之后，
区域仍然存在，只是**不再描述任何真实内容**。

修法不是"到处记得清空"（那种写法一定会漏一处），而是给区域配一个凭据：

```ts
export function previewRegionsFor(document, regions, signature) {
	if (!regions || regions.length === 0) return [];
	if (!signature) return [];
	return signature === clipExtentSignature(document) ? regions : [];
}
```

- 预览时把 `clipExtentSignature(document)` 一起写进 store；
- 组装场景前先过 `previewRegionsFor`，签名不符就返回空数组；
- 重新分析、Discard、Apply 三处都显式清空（清空也清签名）。

`clipExtentSignature` 是仓库里已有的函数，`appendAutoZoomSuggestions` 用它防"建议过了几秒才落地时
clip 已经变了"——预览面对的是同一个问题，所以用同一个凭据，没有新造一套。

## 3. 真机证据

两个工程：A 是那段有 2 次点击的 15 s 录屏（2880×1800），B 是另一段 4 s 素材（1920×1080）。

```
1. 打开 B（从未预览过）        → leak-base.png
2. 打开 A → 分析 → 点 Preview  → leak-previewed.png
3. 照片仍在 store 的时候切回 B  → leak-after.png

diff(B base, A previewed) = 658858 px   ← 两个不同工程，本来就该差很多
diff(B base, B after)     = 0 px (0.000%)  ← 预览没有跟过来
```

第 3 步是关键：切回 B 时 `previewZooms` **还在 store 里**（我没有依赖清空），B 的画面仍与
"从未预览过的 B"逐像素相同，说明拦在场景组装那一层的签名校验确实生效了。

**这一项没有单测**：`previewRegionsFor` 是纯函数，本可以轻易写三条，但我把预算放在真机上，
因为要防的正是"跨组件、跨工程"的泄漏，而那只有真机跑得出来。报告里如实标为"仅真机证据"。
