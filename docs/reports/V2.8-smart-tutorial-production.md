## 2. 复用了什么（没有重写规划器）

| 已有 | 用途 |
|---|---|
| `collectAutoZoomSuggestionsForDocument(document, getTelemetry)` | 生成建议，`getTelemetry` 由 sidecar 的 samples 提供 |
| `appendAutoZoomSuggestions(document, suggestions)` | 纯函数，返回新 document |
| `store.setDocument(..., { history: false })` + `store.saveDocument(..., { history: true, historyBase })` | 一次批量写入 = 一条撤销历史 |
| `Toggle` / `SliderCell` / `sliderGrid` | 面板样式 |

**写入的真实类型是 `ZoomRange`**（`zoomRanges`），不是 `ScreenMotionRegion`。`appendAutoZoomSuggestions`
用 `anchorRegionsWithDerivedMs` 把时间轴跨度锚到 clip 上，所以 Split / Trim / 重排由既有锚点逻辑负责，
我没有自己算时间。

## 3. 面板入口

「光标」面板末尾加了 **Smart zoom** 一组：状态文字（未分析 / 已找到 N 条）、三个按钮
（Analyse clicks / Apply all / Discard）。

设计上把两件事分开：
- **分析**只把建议放在组件 state 里，磁盘上的 `zoomRanges` 一条不动；
- **Apply all** 才写文档，并且是一次写入。

## 4. 真机数据（真实 Electron + 真实 sidecar）

素材 `recording-1794219210593.mp4`（15.02 s，2880×1800），sidecar 里有 2 次点击
（1 × click + 1 × right-click）和 467 个 move 样本。

```
ZOOMS_0            0
ANALYSED           Found 1 suggestion(s)
APPLY_ENABLED      true
ZOOMS_AFTER_APPLY  1
ZOOMS_AFTER_UNDO   0
ZOOMS_AFTER_REDO   1
```

- 2 次点击只生成 **1 条**建议：规划器把它们合并成了一段，这不是"一点一击一个 zoom"；
- 三个数字都是从**磁盘**读的（每次操作后 Ctrl+S），不是同一会话的内存值；
- 一次 Ctrl+Z 把 1 条整批撤回 0，一次 Ctrl+Shift+Z 回到 1。
