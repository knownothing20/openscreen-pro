## 2. 步骤建议的算法（`src/lib/ai-edition/timeline/stepSuggestions.ts`）

输入只有 sidecar 里的鼠标样本，所以能判断的只有"这些点击属于同一件事"，
不能判断"用户打开了设置"。因此：

**建议只带时间，标题由 UI 现场生成**（`Step {n}`，按当前语言）。从 (x, y) 猜"打开设置"
是编造，不做。

两条切分信号，都是人描述录屏时真正会用的：

| 信号 | 默认值 | 理由 |
|---|---|---|
| 停顿 | ≥ 2500 ms | 够读完一段话，说明换事了 |
| 跳区域 | ≥ 画面 28% 的对角线 | 换地方操作 |

两个都**对着组内首个点击**判断，不是对上一个点击——缓慢横扫屏幕时，每一小步都不远，
但累计位移很大；对上一个点击比较会把两个步骤合成一个。

`move` 样本一律忽略：把光标划过也算一次动作，30 秒素材能切出四十个"步骤"。

上限 8 条，取最早的（教程从头看）。

7 条单测覆盖：忽略 move、同区域合并、停顿切分、区域切分、累计漂移、上限、无点击。

```
MARKERS_0              0
ANALYSED               Found 1 step(s)

ROWS                   ["Step 1  5.5s"]
MARKERS_AFTER_APPLY    1
MARKER_SAMPLE          {"id":"marker_d5b1ba9f…","assetId":"asset_main",
                        "sourceTimeSec":5.466,"label":"Step 1","createdAt":"…"}
```

`saveDocument(history:true, historyBase)`，所以是一写一撤。
