## 2. 预览怎么实现的（没有第二条渲染路径）

关键是**在场景下发前拼一份临时 document**，而不是写工程：

```ts
// NativeCompositorOverlay：组装 scene 时
const sceneDocument = previewZooms.length
  ? { ...document, zoomRanges: [...document.zoomRanges, ...previewZooms] }
  : document;
const base = buildSceneDescription(sceneDocument, webcamSourceSize);
```

`previewZooms` 是 `projectStore` 里一个**不属于 document** 的字段（`setState` 设置，不经
`setDocument`/`saveDocument`），所以：

- 画面真的变了——它走的是同一条 `buildSceneDescription` → 合成器路径；
- 工程没变——`document.zoomRanges` 没被碰；
- 没有历史——没调用任何记 history 的写入；
- 关掉就没了——清空数组，effect 重跑，scene 回到原样。

预览用的区域是 `appendAutoZoomSuggestions(document, [suggestion])` 算出来的**同一份锚定结果**，
所以预览看到的就是应用后会落下的东西，不是另算一个近似值。

## 4. 上一轮"A2 时间精度"的更正

上一轮我说 `4.966 vs 5.0` 是"一帧误差"，任务书指出 34 ms 在 60 fps 下接近两帧，这个说法不严谨。
本轮没有改 Seek：显示值来自 `span.start / 1000` 的 `toFixed(1)`，即 UI 把 `4966 ms` 显示成 `5.0s`，
而跳转传的就是 `4966`——**UI 的四舍五入，不是定位误差**。所以这里没有产品缺陷，也没动 Seek。
