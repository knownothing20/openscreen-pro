## 3. 面板做了什么

在「光标」面板末尾加了一组 **Shortcut cards**：

- 总开关（`cursor.shortcutShow`）；
- 位置四选一（顶 / 底 / 左下 / 右下，`aria-pressed` 表示当前项）；
- 三个滑块：卡片时长 500–6000 ms、字号 2–12%、不透明度 —— **不透明度被移除，见 §4**；
- 恢复默认（写回 `DEFAULT_SHORTCUT_OVERLAY`）。

打开这个功能不需要改 JSON：

```
SWITCHES ["Show shortcut cards"]
TOGGLE_FOUND 1  pressed false
AFTER_CLICK true
SLIDERS [{"Card duration":"1500"},{"Card font size":"5"}]
```

点击前后同一时刻（7.6 s）的预览截图：卡片区深色占比 **0.0037 → 0.0135**，差 **4821 px（0.479%）**。
数字比上一轮（0.0226）低，是因为默认时长 1500 ms、字号 5%，都比上一轮手写的 2000 ms / 6% 小。

保存与新进程：

```
OPEN_1 pressed true
DISK {"enabled":true,"durationMs":1500,"position":"bottom-center",
      "fontSizeRel":0.045,"background":"#111318","color":"#f4f6fb","radiusPx":10,"opacity":0.92}
OPEN_2 pressed true
SLIDERS ["Card duration=1500","Card font size=5"]
```

第二条 `OPEN_2` 是**另一个 Electron 进程**读回来的，不是同一个会话里的内存值。

## 4. 不透明度：滑块做了又删掉

上一轮发现 `opacity` 存了不生效（`SceneAnnotation.text` 没有 alpha 字段）。这一轮我先加了滑块，
随后按任务书「不得保留一个用户可以调节但实际不生效的滑块」把它**删掉**了，位置留了一行注释说明
去除原因。

没有去猜 8 位 hex alpha 是否被 `parse_hex` 接受——那是需要读合成器才能确认的事，本轮预算不够，
我不想用一个可能被静默丢弃的值去冒充"已实现"。

## 8. 现在用户能做什么

1. 打开一个录屏工程（带 `shortcuts` 的 sidecar）；
2. 右侧「光标」面板 → **Shortcut cards** 打开；
3. 选位置、调时长与字号；
4. 预览里立刻看到卡片；
5. Ctrl+S，重开仍然是开的；
6. 导出（CLI 已验证）里有卡片。

这是一条**不需要碰 JSON** 的完整链路。
