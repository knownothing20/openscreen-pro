## 2. 本轮为什么停在这里

任务书要求一次做完四个模块，并跑完 20 步真机验收。这一轮的上下文预算在审计完成、
判定层落地之后就基本用尽——继续往下写场景接线、面板 UI、四类回归、两种编码导出与打包，
只能产出未经运行验证的代码。**没有验证过的代码比没有代码更糟**，它会把"看起来做了"
留给下一个接手的人。所以按任务书「如果某项被环境阻塞，继续完成其他独立任务，明确标记
NOT_RUN/BLOCKED，不降低标准」这一条收尾，而不是把没跑通的东西写进报告。

这不是环境阻塞（Electron、Playwright、addon、FFmpeg、NSIS 都在），是**这一个回合装不下**。

## 3. 审计：四件事里三件的底座已经存在

| 功能 | 已有实现 | 真正缺失 | 复用方案 |
|---|---|---|---|
| 快捷键采集 | Sidecar v3 的 `shortcuts: CursorShortcutEvent[]`，`electron/media/cursorSidecar.ts` 解析、`normalizeCursorShortcut` 已做隐私过滤 | **全部可视化层**：没有任何前端代码读这个字段 | 新建判定层（本轮已做）+ 场景注入 |
| 自动运镜 | `src/lib/ai-edition/timeline/zoom-suggestions.ts`（完整的停机/合并/引子常量）、`apply-auto-zooms.ts`（`collectAutoZoomSuggestionsForDocument`、`appendAutoZoomSuggestions`、`clipExtentSignature`） | **UI 入口、预览、应用按钮** | 直接复用规划器与写入器 |
| Spotlight | `ScreenMotionRegion.focusEffect?: FocusEffect` 已在数据模型里（`screenMotion/resolve.ts:81`），`focusEffect.ts` 有实现 | 与建议一起生成/开关联动 | 复用，不新建高亮通道 |
| 操作标记 | 录制 Marker 与时间线标记已有 | 建议生成与编辑 UI | 复用 Marker，不建章节库 |

两个结论值得记下来：

1. **"自动运镜"不是从零开发**——规划器和"写进时间线"的函数都已在仓库里，缺的是把它接到
   一个用户能点的入口上。任务书里"历史审计显示已有 zoom-suggestions 规划器"是对的。
2. **"Spotlight 联动"的数据通路已经通了**——`focusEffect` 是 `ScreenMotionRegion` 的可选字段，
   并且注释说明了它对旧文档是"缺省即无"，不需要 `schemaVersion` 升级。也就是说模块 C 的
   工作量主要在 UI 与生成时填字段，不在合成器。

## 4. 交付：快捷键浮层判定层（唯一完成的东西）

新增 `src/lib/ai-edition/timeline/shortcutOverlay.ts`。

```ts
shortcutCardAt(shortcuts, settings, atMs) → { combo, pressedAtMs, progress } | null
```

它只回答一个问题：**这一帧该不该画、画哪张卡**。设计要点，逐条对应任务书的要求：

| 要求 | 做法 |
|---|---|
| 不复制原始数据到工程 | 纯函数，不写 document，卡片永远不是工程对象 |
| 同一时间点结果确定 | 只依赖 `(shortcuts, settings, atMs)`，无隐藏状态 |
| 反向 Seek 不残留 | 没有"上一张卡"可残留；窗口是半开区间 `[t, t+duration)` |
| 无 shortcuts 时不出浮层 | `null` 直接返回 |
| 隐私过滤 | `looksLikeChord()` 在**绘制端**再挡一次：`Ctrl+Shift+P` 通过，`hunter2`、`a`、`Ctrl`、整句文本全部拒绝 |
| 重叠时显示最新的 | 后按下的赢，同时间戳取文件中靠后的 |

`DEFAULT_SHORTCUT_OVERLAY` 里 `enabled: false`——浮层默认关，和快捷键采集默认关保持一致。

**测试 8 条**（`shortcutOverlay.test.ts`）：开关关闭、无数据、窗口边界（1999/2000/2999/3000）、
正反向采样一致、重叠取最新、`progress` 用于淡入淡出、四类非组合串全部拒绝、
`looksLikeChord` 的正反例。

**负向验证**：把 `elapsed >= duration` 这个门控去掉后，`shows the chord only inside its window`
与 `answers the same whichever direction` 立刻变红（2 failed / 6 passed）；恢复后 8/8 绿。
这条验证也顺带说明门控是**真的**在起作用，不是写在注释里。

## 5. 场景接线为什么没做（接法已定位）

`buildSceneDescription(document)` 是**同步**的（`src/native/sceneDescription.ts`，导出侧在
`CliExportRunner.tsx:291` 调用），而快捷键在 sidecar 里要靠异步读文件（`cursor.getRecordingData`）。
一个只吃 `document` 的同步函数拿不到那份数据。

而 `SceneAnnotation` 本身**已经够用**：`kind: "text"` + `content` + `backgroundColor` +
`color` + `fontSizeRel` + `animation`，正是按键卡片需要的东西（`sceneDescription.ts:258`）。

所以接线只有一种形状：**在 scene 构建之后、下发之前**追加一个 annotation，而不是改构建器。
需要两处改动：

1. 一个按路径缓存的 `shortcutsOf(videoPath)`（照抄 `stateChangesOf` 的缓存写法）；
2. 预览与导出两个下发点各追加一次 —— 两处都要，否则会重演 V2.7.2 那种"预览有、导出没有"。

**圆角要注意**：`SceneAnnotation` 没有 `radiusPx` 字段。任务书要求浮层支持圆角，若合成器
不支持，按任务书自己的规则（"不为少数边缘效果重写 shader"）应当先不做，而不是偷偷忽略。
