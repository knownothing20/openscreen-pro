## 2. 编辑走的是文档自己的函数

没有新建 Marker 服务，直接复用 `document/markers.ts` 里已有的：

```ts
setMarkerLabel(document, id, label) → AxcutDocument
removeMarker(document, id)          → AxcutDocument
```

两者都是纯函数，改的是"返回一份新 document"，因此 id / assetId / createdAt 天然保留——真机验证里
`id kept: true`、`assetId kept: asset_main` 就是这个的后果，不是额外写代码保住的。

两个操作共用一个 `writeMarkers`（`setDocument(history:false)` + `saveDocument(history:true,
historyBase)`），所以改名一次撤销、删除一次撤销，**不是每个字符一次**。输入框在 `blur` / `Enter`
时才提交，`Escape` 还原。

## 4. 两个自己挖的坑

**坑一：zustand selector 里 `?? []` 导致无限渲染**

```ts
const appliedMarkers = useProjectStore((s) => s.document?.markers ?? []);
```

每次渲染都分配一个新数组，store 认为状态变了 → `Maximum update depth exceeded`，直接把
`RightPanes.i18n.test.tsx`（法语/德语两个用例）和 `CursorPane.preview.test.tsx` 打红。
改成模块级常量 `EMPTY_MARKERS` 后 10/10 通过。

**坑二：审计表的记账名是"实际写入点"，不是调用者**

我先登记了 `renameMarker` / `deleteMarker` 各两条，测试报 `expected 110 / received 112`——
因为真正的写入发生在共用的 `writeMarkers` 里，扫描器记的是它。改成 `writeMarkers` 两条才对。

## 5. Spotlight 为什么仍是 NOT_RUN

按任务书的审计结论：原生 Spotlight 已存在（`SceneFocusEffect`、mode 19 遮罩、在屏幕内容之后
光标之前绘制），但它读的是 `screen_motion_regions`，而自动运镜写的是 `zoomRanges` →
`SceneZoomRegion`。两者是不同结构，**不能给 ZoomRange 加个字段就指望原生消费**。

接通它需要：改 `SceneZoomRegion` 的 Rust serde 结构 → 改 `frame_geometry.rs` 里的坐标变换
（zoom.focus 是源画面坐标，Spotlight 需要输出画布坐标，中间还隔着裁剪、aspect、Zoom 本身、
Screen Motion、3D 倾斜）→ 重编 compositor addon（`crates/target` 已删，要全量重编 15–30 分钟）
→ 真机视觉验收。

这不是一次能塞进本轮尾巴的改动，硬做只会产出一个「字段加了但画面没变」的东西。我选择不做，
而不是假装做了。
