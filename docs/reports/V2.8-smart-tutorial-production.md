## 3. 真实 MP4 逐帧测量（本轮新增）

素材：`recording-1794219210593.mp4`，sidecar 里 `Ctrl+Alt+F9 @ 7.49 s`。
快捷键设置 `durationMs = 1500`，导出 H.264，输出 **1920×1080 / 60 fps**。

**测量方法**：卡片是画面下方偏右的深色圆角块（相对区域 x 0.435–0.625、y 0.760–0.815）。
把该区域裁出来缩到 64×16、取每帧灰度均值——卡片在时均值从 254 掉到 149。
逐帧扫这条曲线，第一个和最后一个低于阈值的帧就是卡片的上/下边界。

| 工程 | 输出帧数 | 卡片帧区间 | 时长 | 判断 |
|---|---|---|---|---|
| 全段 2× | 450 | 225 → 314 | **90 帧 = 1500 ms** | 起点 3.750 s，预期 3.745 s（差 0.3 帧） |
| 全段 0.5× | 1802 | 899 → 988 | **90 帧 = 1500 ms** | 起点 14.983 s，源 7.49 s 在 0.5× 下的位置 |
| 2× + 源 8 s 处连续 Split | 450 | 225 → 314 | **90 帧 = 1500 ms** | 跨越成片 4.0 s 的切点，没有重新入场 |
| 2× + 丢掉源 8–10 s | 390 | 225 → 239 | **15 帧 = 250 ms** | 在 4.0 s 切点处停止，没有飘到无关画面 |

**旧代码的对照**：同一工程、同一设置，在重新构建前导出的版本卡片只持续约 0.75 s
（t=4.0 s 有卡片、t=5.0 s 已消失）。重建后 5.1 s 仍有、5.4 s 才消失。这就是那个
「1500 ms 在 2× 下只剩 750 ms」的 bug，在成片里被直接看到、也被直接修掉了。

**输入时间基准的核对**（任务书要求重点确认）：`outputDurationOfRawSpan(from, to, speedRegions)`
的 `from/to` 与 `speedRegions` 的 `startMs/endMs` 都在**源秒**这条尺子上——`speed.ts` 的注释写明
"Regions are matched on the raw ruler, the same coordinate their pills are drawn in"。
卡片事件的 `event.timeMs` 也是源时间。所以三者同基准，中间没有混用 Raw Timeline 时间。
上面 0.5× 那行是最直接的证明：若把成片时间当成源时间喂进去，0.5× 下会算出 3.0 s 的跨度而不是 0.75 s。

## 3.5 Spotlight 审计结论（本轮新增，未实现）

### 关键发现：不需要改 Rust

`crates/compositor/src/screen_motion.rs::focus_effect_sample_at` 只读两样东西：

```rust
let effect: SceneFocusEffect = region.focus_effect?;   // 中心/大小/柔化/压暗
let progress = camera_motion_easing_fn(&region.easing)(phase);  // 时间包络
```

它**从头到尾不看 `region.target.scale`**。所以一条 `target.scale = 1` 的
`SceneScreenMotionRegion` 会被正常当作遮罩来源，而 `frame_geometry` 里它对画面的放大是 1×，
即不缩放。遮罩仍画在屏幕内容之上、光标之前（mode 19），位置由 `effect.centerX/centerY` 决定。

这意味着「自动 Zoom 的 Spotlight」可以用**纯 TypeScript** 接上：

```
zoomRange (已有)
  → 追加一条 screenMotionRegion { target.scale = 1, focusEffect: {...} }
  → scene.screenMotionRegions
  → focus_effect_sample_at 画遮罩
```

`target.scale = 1` 是这条路径成立的关键——它满足「不为 Spotlight 伪造一条**会缩放**的
ScreenMotionRegion」，因为这条 region 确实不缩放。

### 但还有三件事没做完，所以本轮标 NOT_RUN 而不是 PASS

1. **坐标**：`zoomRange.focusX/focusY` 是**源画面**坐标（0..1），`focusEffect.centerX/centerY`
   是**画布**坐标。Zoom 放大后，目标点会朝画布中心移动，边缘还会被 clamp。直接抄 focusX/focusY
   会让遮罩偏在画面一角。正确做法是照 `frame_geometry.rs` 的 zoom 变换反推目标点在画布上的位置
   （含 crop / aspect / 边界 clamp）。这一步没做，所以现在接上去必然错位。

2. **接入点**：`src/native/sceneDescription.ts:1797` 是 `screenMotionRegions` 的构建处，
   `projectedScreenMotionRegions` 由文档里的 region 投影而来。Spotlight region 要在这一步之后
   追加，且必须与人工 Focus Effect 做优先级合并（人工优先，不允许两层遮罩叠加）。

3. **验证**：需要同工程导出「原始 / Zoom-only / Zoom+Spotlight / 关闭 Spotlight」四片并量化
   焦点位置与缩放尺度。这是判断"没有二次缩放"的唯一证据，单元测试给不了。

### 接续的具体起点

```ts

//    zoomScaleAt(t) 与 zoomFocusToCanvas(focusX, focusY, scale) 的等价公式
// 2) 在 sceneDescription.ts:1797 之后追加：
//    for each zoomRange with spotlight enabled and no人工 focus covering the span:
//      push({ startSec, endSec, clipIndex, target: { positionX: .5, positionY: .5, scale: 1, ...0 },
//             focusEffect: { shape, center: <canvas point>, size, softness, dimming, ... } })
```

### 为什么不是 programme→source 的换算

Marker 存的是**源时间**，而 raw timeline 就是"源时间 + clip 偏移"，所以 clip 内是线性的：

```ts
sourceTimeSec = clip.sourceStartSec + (rawTimeSec - clip.timelineStartSec)
```

Speed 改变的是"一秒源时间播放多久"，不是"它坐在哪"，所以**变速不需要换算**。真正的陷阱是把
programme 时间写进去——那会让 marker 在变速后漂移。这一条写进了 `markerSourceTimeAtRawTime` 的注释。

反查不到 clip 时返回 `null` 而不是就近吸附：把 marker 悄悄绑到另一条素材上，比不动更糟。

### 合并规则（首版）

只允许同一 `assetId`；`sourceTimeSec` 取最早；保留最早那条的 id / label / createdAt（引用仍有效）；
其余删除；一次写入 = 一条 Undo（走共用的 `writeMarkers`）。

### 实现

**Rust**（`scene.rs` + `frame_geometry.rs`）：`SceneZoomRegion` 增加 `focus_effect`，并在
`focus_effect_sample_at` 之后加一条回退：

```rust
let authored_focus = focus_effect_sample_at(screen_motion_regions, source_t, &clock);
let auto_focus = || -> Option<FocusEffectSample> {
    let effect = <覆盖 source_t 且带 focus_effect 的区域，取 start_sec 最大者>;
    if zoom_strength <= 0.0 { return None; }         // 门 = zoom 自己的包络
    Some(FocusEffectSample {
        center: [s_dst[0] + p.focus[0] * s_dst[2],
                 s_dst[1] + p.focus[1] * s_dst[3]],
```
