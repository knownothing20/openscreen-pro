## 2. 本轮真正的发现：这个映射不需要换算时间基准

上一轮我以为要在源时间和节目时间之间做换算（`programmeTimeSec`、trim、speed）。查
`SceneDescription.annotations` 的注释后才发现不需要：

> Annotations projected onto each clip's **source time**, ascending by `zIndex`…

scene 里的 annotation 是**按源时间 + `clipIndex`** 寻址的，而快捷键事件的 `timeMs` 本身就是源时间。
两者同一坐标，中间没有任何换算。

这不是省了活，而是让正确性变成结构性的：

| 场景 | 结果 | 为什么不用写代码 |
|---|---|---|
| Trim 掉了那段 | 卡片消失 | 事件落在 `[sourceStartSec, sourceEndSec)` 之外，匹配不到 clip |
| Split 了 | 卡片落在真正播放它的那一侧 | 两段的源窗口互斥，事件只落进一段 |
| 重排 | 卡片跟着走 | 它带的是 `clipIndex`，不是时间轴位置 |
| Speed | 卡片时长按**源时间**算 | 变速改变它停留多久，不改变它发生在录制的哪一刻 |
| 跨两个素材 | 各用各的 sidecar | 按 `screenPath` 过滤 |

`shortcutCardSpans(clips, events, settings, videoPath)` 就是把这条落成 20 行。

**一处我原来想错的地方**：我以为 split 会让同一张卡片出现两次。实际上源时间 2.5 s 只属于切点
左侧那一段，右侧那段播的是 3 s 之后，所以只出现一次——两个测试最初都按错的理解写，
失败后改的是期望，不是实现。

## 4. 接线为什么又没做完（这次的坑很具体）

要真正画出来，需要三件事，我在第二件上失败并回滚：

1. **适配器** `withShortcutOverlay(scene, document)`：调用 `nativeBridgeClient.cursor.getRecordingData`
   拿 `shortcuts`（按路径缓存 promise），再用 `shortcutCardSpans(scene.clips, …)` 生成
   `SceneAnnotation`（`kind: "text"` + `content/color/backgroundColor/fontSizeRel`）。
   这份代码我写完并编译通过了，已随回滚删除——它依赖第 2 件的设置字段。

2. **设置字段**：`cursor.shortcutOverlay`。**这里有三层默认值对象，不是一个**：
   - `src/lib/projectDefaults.ts` 的 `DEFAULT_PROJECT_APPEARANCE.cursor`
   - `src/components/video-editor/editorDefaults.ts` 的 `DEFAULT_CURSOR_SETTINGS`（引用了上一层的 `.cursor.aperture`）
   - `src/lib/ai-edition/store/editorSettings.ts` 的 `DEFAULT_EDITOR_SETTINGS.cursor`
   再加上 `CursorVisualSettings`（`src/components/video-editor/types.ts:286`）的字段、`LegacyShape` 的
   `cursorShortcutOverlay?: unknown`、读取 `readShortcutOverlay`、写入一行。
   我连续几次靠字符串替换猜位置，每次 tsc 都指出"这个对象里没有那个键"，说明我猜的不是同一个对象。
   **继续猜的代价是留下一个编译不过的仓库**，所以停手回滚。

3. **三个调用点**（都确认了）：
   - 预览：`NativeCompositorOverlay.tsx:157`
   - 导出：`CliExportRunner.tsx:291`、`ExportDialog.tsx:404`
   三处必须都调同一个 `withShortcutOverlay`，只接一处就会重演 V2.7.2 的"预览有、导出没有"。

下一步只需把第 2 件按对象逐个补（读文件确认位置，不要字符串替换），第 1、3 件照上面的清单即可。
