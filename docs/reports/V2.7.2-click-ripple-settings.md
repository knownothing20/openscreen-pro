## 3. 关键发现：配置写了、导出不变（本轮真因）

第一次导出验证时，**两个只有波纹配置不同的工程导出了字节完全相同的 mp4**——即 UI 与场景层都对，
导出却无视配置。定位过程：

1. 单元测试与 `buildSceneDescription` 直调均输出正确的 `leftEnabled: false`；
2. 强制 `delete sceneDesc.cursor.clickRipple` 后导出画面变化 → 说明 CLI 确实执行了这段代码；
3. 追到 `src/cli/CliExportRunner.tsx:149` 的 `normalizeProjectEditor(project.editor)`：
   `src/components/video-editor/projectPersistence.ts` 的 `normalizeProjectEditor` 是**白名单**，
   逐个透传 `cursorSize` / `cursorSmoothing` / `cursorMotionBlur` / `cursorClickBounce` / `cursorAsArrow` …
   **未知键被静默丢弃**，`cursorClickRipple` 因此到不了 `legacyEditor`。

修复：类型加 `cursorClickRipple?: unknown`，白名单加一条透传。文件里原有的注释已经预言过这类事故
（"A key missing here is a key the export silently drops back to its default"）——这是本轮最容易复发的地方，
**以后给 `legacyEditor` 加 v2 可写键，必须同时改这一处**。

## 4. 真实导出验收（GPU 编码）

素材与工程在 `%TEMP%\os-v272\`（沿用第一轮：1920×1080 / 30 fps / 4 s 纯 `#202020`，光标停在 (0.5,0.5)，
点击在 1 s / 2 s / 3 s，分别为左 / 右 / 中）。命令：

```
electron . export <工程>.openscreen -o <out>.mp4 --codec h264 --quality source
```

每次 240 帧，编码器 `h264_nvenc`（D3D11 零拷贝）。抽帧统一裁中心 600×600。

### 4.1 三键开关（`v4-off`：左键关、中键关、右键开）

| 帧 | 观察 | 判定 |
|---|---|---|
| `t=0.50` | 只有光标 | 对照 |
| `t=1.30`（左键后 300 ms） | **完全无环**（与旧构建的同刻帧有明显灰白环形成对照） | 开关生効 |
| `t=2.05`（右键后 50 ms） | 橙色小环 | 该键仍开 |
| `t=3.05`（中键后 50 ms） | **无环** | 开关生効 |

### 4.2 大小与颜色（`v4-big`：160 px / 900 ms / 0.9 / 左键 `#12ab34`）

| 帧 | 观察 | 判定 |
|---|---|---|
| `t=1.30` | **绿色**环，直径约 90 px（默认配置同刻约 30 px） | 颜色与大小均生効 |

### 4.3 三次导出的互异性（防止"参数没进画面"的假阳性）

| 对比 | 结果 |
|---|---|
| `v4-off` vs `v4-big` | **不同**（`af76b8…` / `577bac…`）→ 参数确实进画面 |
| 修复前的 `off3` vs `big` | **完全相同** → 就是 §3 那个缺陷 |

### 4.4 旧工程视觉兼容

- `still.openscreen`（无 `cursorClickRipple`）的场景 JSON 与 V2.7.1 **逐字相同**：派生分支直接写字面量
  `[1,1,1,1]` / `[1,0.62,0.2,1]` / `[0.35,0.7,1,1]`，不经 hex 往返（`0.62`、`0.7` 没有精确的 `#rrggbb` 表达）。
  三个 `leftEnabled` 等键不写 → addon 用 serde 默认 `true`。
- 单测锁定：`keeps the pre-V2.7.2 rule when the project stores no ripple settings`。
- **已知差异**：若用户在 UI 里显式保存一次默认值，中间键的蓝分量从 `0.7` 变成 `179/255 = 0.702`，
  与旧画面 PSNR **84.3 dB**（min 77.5，部分帧 `inf`）——肉眼不可辨，但不是零。这是 hex 无法精确表达
  `0.7` 的必然结果；要彻底归零需把默认色改成 `#59b2ff`，本轮没改（会牺牲取自 `0.7×255` 的直觉值）。

## 6. 未完成事项与风险

| 项 | 状态 / 说明 |
|---|---|
| 圆点 / 圆环分离 | **NOT_RUN**。前提已验证：HLSL `mode 4` 分支（`shaders.hlsl:4010-4031`）与 Metal（`shaders.metal:3625-3645`）都**不读 `src`、不读 `uv`**，VS 的 `uv` 由 `src` 算出但 mode 4 不消费 → `src.x` 可作标志位、`LayerCB` 布局不变。**但 Linux 的 `vk_shaders/layer.wgsl` 根本没有 mode 4 分支**：分支链从 `mode < 1.5` 直接跳到 `mode > 4.5`，mode 4 会落到 `else` 的 mode 2 阴影实现。这是 V2.7.1 引入波纹时就存在的跨平台缺口，本轮未修，**直接影响四组 GPU 验收** |
| 轨迹 / 光圈 | **NOT_RUN**。现有 `CursorPlan.taps` 是运动模糊式拖尾，不是独立轨迹层；「光圈」在本仓库没有现成对应物，需要先定义视觉与参数（半径？亮度衰减？跟随节拍？）再动 shader |
| 四组 GPU（H.264/H.265 × NVENC/AMF） | **NOT_RUN**，本轮只跑 NVENC H.264 |
| 性能采样 / 打包 | **NOT_RUN**；未覆盖旧 NSIS |
| 保存 → 退出 → 新进程重开 | **NOT_RUN**（持久化有单测，但没有跨进程重开的端到端证据） |

## 7. 下一步（按依赖排序）

1. **Linux `mode 4` 端口**：给 `layer.wgsl` 补 dot+ring 分支，否则"三平台一致"与四组 GPU 验收都无法成立。
2. **圆点/圆环分离**：`src.x = 1` 启用新语义、`src.y` 为位掩码（bit0 dot、bit1 ring），默认光标的 `src.x = 0` 保持旧行为；
   HLSL / MSL / WGSL 三处同步。
3. 保存重开：一次真实的"改设置 → 保存 → 退出 → 新进程打开 → 再导出"。
4. 四组 GPU 矩阵 + 性能采样，再谈打包。
