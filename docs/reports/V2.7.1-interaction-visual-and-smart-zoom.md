## 2. V2.7 现有代码的复用

| 复用了什么 | 怎么用 |
|---|---|
| `cursor-sampler` 的点击样本 + `interactionType` | 新增 `ClickKind`，直接从 sidecar 解析，未改采集协议 |
| `CursorPlan.impacts` 的绘制循环（三个后端） | 环挂在同一处：Windows `draw_solid`、Linux `make_bind`、macOS `draw_solid`，都在光标之下 |
| **mode 4**（`shaders.hlsl` 的 dot+ring，纯数学） | 环就是一个 mode-4 quad。**未改 shader、未改字节契约、未动 pipeline** |
| `clickBounce` 设置 | 环的开关：0 = 不画。没有新增第二个「点击反馈」开关 |
| `SceneCursor`（`scene.rs`）+ `sceneDescription.ts` | 新字段 `clickRipple?: {durationMs,sizePx,opacity,left,right,middle}`，缺省 = 不画 |

> mode 4 的真实含义已核对：`shaders.hlsl` 里 `mode > 3.5` 分支，按 `quad_px` 用数学画一个 dot + ring（`dot_r=0.34R`、
> `ring_r=0.72R`），不采样任何纹理。三个后端都通过 `draw_solid`/`make_bind` 走同一个 `LayerCB`，因此不需要每平台各写一套。

## 3. 新增功能

- **点击环**：每个仍存活的点击生成一个方 quad，从 `sizePx` 的 35% 长到 100%，alpha 按 `(1-p)^1.5` 衰减，
  450 ms 后消失；中心是**点击的原始坐标**，不是平滑后的光标位置。
- **按按钮分色**：左键白、右键橙 `[1,0.62,0.2,1]`、中键蓝 `[0.35,0.7,1,1]`。
- **关闭**：把「点击弹跳」调到 0，场景里不再带 `clickRipple`，合成器一个环都不画。
- **倾斜屏**：不画（环是屏幕空间的标记，贴在平面上会撒谎）——明确记为限制，不静默画错。

## 5. 数据流

```
.cursor.json (v3)  interactionType: click / right-click / middle-click
   → CursorTrack::from_json  → clicks + click_kinds
   → plan_cursor  (每个 t：取 (t−450ms, t] 内的点击)
   → LayerCB { mode: 4, dst: 点击点为中心的方框, color: 按钮色 × 衰减 }
   → CursorPlan.ripples → 三个后端在光标之下绘制 → 预览与导出同一份
```

## 9. 导出证据

真实导出（CLI，独立 userData，AMD 机器默认硬件编码）：

```
输入   os-v27-rec2/take.openscreen（15.024 s，含 1 次右键、1 次左键、1 次滚轮、Ctrl+Alt+F9）
命令   export ... -o out-h264.mp4 --codec h264
输出   9,813,100 B，902 帧，1598×1080
```

抽帧对比：`t=4.80` 与 `t=5.75`（右键后 284 ms）两帧**字节不同**（546,706 vs 548,345 B），全帧差异 1,390 个强差异像素。
**但这次点击落在画面最底边（cy=0.997）、背景是橙色壁纸，且帧间 UI 本身在变**，逐像素差异铺满全帧，
**无法据此把环单独指认出来**。所以：导出路径已接通，**视觉确认未完成**，不写 PASS。
