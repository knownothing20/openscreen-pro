# OpenScreen V2.7 — 鼠标/键盘事件通道（本轮交付报告）

**结论先说：`OPENSCREEN V2.7 ≠ COMPLETE`。**

本轮把「操作事件数据通道」做成了真实可用的一条链（原生采集 → 主进程映射 → 磁盘 v3 旁挂文件 → 现有自动运镜消费），并用真机录制验证。

## A. 开发总结

### 本轮真正新增

1. **原生采样器的完整指针事件**：右键、中键、滚轮，和左键并列输出；按下/释放分开。
2. **单调时钟**：每个样本同时带 `monotonicMs`（进程启动起的 steady clock）与原有的 `timestampMs`（墙上时钟）。
   主进程用 `ready` 里的双时钟对把 steady clock 锚到本次录制上，**时间映射不再读墙上时钟**。
3. **键盘快捷键采集（默认关闭、需主动开启、Windows only）**：`--keys` 时安装 `WH_KEYBOARD_LL`，
   只在按住 Ctrl/Alt/Win 时上报虚拟键码，**不产生字符、不产生文本、不碰剪贴板**。
4. **点击语义**：`click` / `right-click` / `middle-click` / `double-click`（时间+距离窗口内合并）/ `mouseup`。
5. **存储 v3**：`<video>.cursor.json` 增加 `shortcuts: [{timeMs, combo}]` 与样本级 `wheelDelta`；v2 文件照常读。
6. **隐私过滤的独立模块与测试**：白名单按键 + 必须带 Ctrl/Alt/Win + 600 ms 防抖 + 上限 2000 条。
7. **一个面向用户的开关**：Record 模式里的「快捷键」行（中文界面），15 个语言都补了文案。

### 已有能力（本轮只复用/验证，不算新增）

- **自动运镜**：`zoom-suggestions.ts` 早已有「点击 → 分镜 → 合并 → 避免来回缩放 → 按 clip 锚定」的完整规划器，编辑器导入新录制时会自动落 `zoomRanges`。
  本轮只证明**新记录的右键/中键/双击同样能驱动它**（新增 4 条测试），没有改规划器。
- **Spotlight（Focus Effect, mode 19）**：屏幕运镜区域上的独立压暗/聚光，早已存在且可编辑。未改动。
- **步骤标记**：`add-recording-marker` IPC 与时间轴标记早已存在。未改动。

## B. 架构设计：事件如何采集、存储、映射

```
cursor-sampler.exe (C++/Win32, 33 ms 轮询)
  ├ WH_MOUSE_LL  : 左/右/中键的次数、滚轮增量（低层钩子，计数后由采样线程取走）
  ├ WH_KEYBOARD_LL (仅 --keys): 按住 Ctrl/Alt/Win 时的 VK 码
  ├ GetCursorInfo: 物理屏幕坐标（per-monitor-v2 DPI aware）
  └ 每 tick 一行 JSON：timestampMs + monotonicMs + x/y + 三个键状态 + wheelDelta
        │  stdout(NDJSON)
        ▼
WindowsNativeRecordingSession (main process)
  ├ ready 事件 → originMonotonicMs / originWallMs
  ├ timeMs = monotonicMs − originMonotonic + (originWall − takeStart)     ← 不再读墙上时钟
  ├ 坐标：物理像素 → 目标矩形归一化 0..1（窗口捕获用采样器给的 GetWindowRect，显示器捕获用 DIP→物理换算）
  ├ 语义：按下 → click/right-click/middle-click；450 ms 内同键且 0.03 内 → double-click（前一条降为 move）
  └ ShortcutCollector：白名单 + 必须带修饰键 + 600 ms 防抖 + 上限
        │
        ▼
<video>.cursor.json  (v3, 与视频分离，不进工程 JSON)
        │
        ├→ readCursorTelemetryFile → 渲染进程 → zoom-suggestions → zoomRanges（既有自动运镜）
        └→ readCursorSidecar → agent / 诊断
```

**坐标规则**：采样器从不把坐标当视频像素。它给的是**物理屏幕像素**，主进程用「本次捕获的物理矩形」归一化；
窗口捕获优先用采样器随样本发来的 `GetWindowRect`（已是物理），显示器捕获才用 Electron 的 DIP bounds 经 `toHelperRect` 换算。
多显示器/DPI 的既有分支没有改，只在其中新增了按键语义。

**为什么不进工程 JSON**：事件跟着视频走（`<video>.cursor.json`），工程只引用资产路径。这样复制工程、重开、删除资产的行为与既有媒体链接一致；
缺失旁挂文件时读取方拿到空事件并提示（既有 `readCursorSidecar` 语义），不会破坏工程。

**版本与兼容**：`version: 3`。v2（无 shortcuts、无 wheelDelta）照常读；v3 的 `shortcuts` 条目若缺字段/时间非法则丢弃，不做「修复」，
因为一个从未按过的组合键没有安全的修复值。

## D. 真实录制证据

全部为本机真机录制，使用 CLI + 独立 `--user-data-dir`，不触碰既有用户配置。

| 项 | 15 s 验证录制 | 600 s 录制 |
|---|---|---|
| 视频 | 2880×1800 h264, 15.024 s, 20,332,297 B | 2880×1800 h264, 600.054 s, 873,506,228 B |
| 样本数 | 471 | **17,809** |
| 旁挂文件 | 100,732 B（v3） | **3,792,682 B**（v3） |
| 时间范围 | 0 – 15,087 ms | 0 – 600,161 ms |
| 单调性 | 非降 | **非降** |
| 采样间隔 | 33 ms 配置 | **中位 34 ms，最大间隔 50 ms** |
| 事件 | 右键 ×1、左键 ×1、mouseup ×2、滚轮 +120 ×1、`Ctrl+Alt+F9` @7489 ms | 无输入（纯漂移测试） |

存储增速：3,792,682 B / 600 s ≈ **6.3 KB/s**，即 30 分钟约 11.4 MB（**这是按实测速率推算，不是 30 分钟实测**）。

时间同步误差：本轮**没有独立的高精度时钟基准**去测「事件 vs 帧」的绝对误差（需要外部时码或高速摄影）。
可以说的是：600 s 内时间轴单调、无回跳、无丢样本，映射链上唯一的墙上时钟只在 `ready` 用一次。

## L. 下一版本建议

只列真正影响交付的：

1. **先做点击波纹（原生）**：用既有 mode 4 圆环几何，在 `plan_cursor` 里按点击时间生成扩散 quad（颜色按左右中键区分），
   三个后端都已有 `impacts` 绘制循环可挂。这是把「已采到的数据」变成「看得见的效果」最短的一步。
2. **快捷键浮层的渲染路径**：复用 annotation 文本层还是新增原生层，需要先定一个，否则数据永远停在 JSON 里。
3. **屏幕运镜的生成器**：`zoom-suggestions` 的规划结果已经是屏幕上的一个矩形，映射到 `ScreenMotionRegion`（position/scale）是纯数学，
   但必须先有编辑器入口与撤销语义，否则只是死代码。
4. **30 分钟 + 导出闭环**：等 1–3 有可导出效果后再跑，避免重复劳动。

不要再往事件通道加字段，除非有消费者。
