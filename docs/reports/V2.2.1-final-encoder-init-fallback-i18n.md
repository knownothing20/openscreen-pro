## 1. 本轮做了什么

### A. 初始化阶段的故障注入（替换掉原来的候选过滤）

上一轮的 `OPENSCREEN_TEST_FAIL_ENCODER` 在**候选规划阶段**把编码器从列表里剔掉——那只证明了"计划器会选下一个名字"，
完全没碰到真正的失败点。

现在注入点移到 `try_open` 内部、**`avcodec_open2` 的正前方**：候选已选定、`avcodec_alloc_context3` 已分配、
参数（含码控）已设置。注入返回的错误**走和驱动拒绝完全相同的路径**——`try_open` 的 `Err` → 候选循环的 `refused`
列表 → 下一个候选（Auto）或硬失败（Manual / CPU）。

**开关是编译期的**，不是运行时约定：
`crates/compositor/Cargo.toml` 新增 `encoder-test-hooks` feature（默认关闭，出货构建里根本不存在这段代码），
env 名也换成了 `OPENSCREEN_TEST_FAIL_OPEN`。用出货构建跑同样的环境变量，结果必须**没有任何变化**——这一点已实测（见 §2 表 B）。

### B. GPU 设置文案的多语言补齐

`encoderSettings.*` 20 个 key + `exportDialog` 6 个 key（`encoderPending/encoderDone/encoderFallback/zeroCopy/systemMemory/encoderGif`），
共 26 个 × 14 个非英语语言 = **364 处**，实际改写 **360 处**（4 处因语言习惯与英文同形，已按 §5 处理为更明确的说法）。
只改值，未重排 JSON：每个文件 `+26/−26` 行，git 统计为 `360 insertions / 360 deletions`，LF 保持。

## 9. 复核修正（2026-11-08 补测）：Auto 的候选顺序与"NVENC→AMF"那条结论

### 9.1 真实顺序（源码 `pipeline_windows.rs:1351-1357`，循环 `:1546`）

```
h264_amf (1) → h264_nvenc (2) → h264_qsv (3) → h264_mf (4) → libopenh264 (5)
```

`open()` 按这个顺序逐项 `try_open`，第一个成功即返回。**AMF 是第一候选，不是 NVENC。**

### 9.2 因此 §2 表 A 那一行的因果是错的

原报告写"Auto + NVENC 初始化失败 → 实际使用 AMF"，暗示"NVENC 失败后回退到 AMF"。实测推翻：

| 运行 | 结果 | 拒绝列表（`écartés`） |
|---|---|---|
| Auto + `FAIL_OPEN=h264_nvenc` | **h264_amf** | **空** —— 说明 nvenc 根本没被尝试 |
| Auto + `FAIL_OPEN=h264_amf` | **h264_mf** | `h264_amf: injected…; h264_nvenc: avcodec_open2 -2 (No such file or directory); h264_qsv: … Unknown error` |

第一行里 amf 在第一次迭代就成功，循环随即返回，`h264_nvenc` 从未进入 `try_open`，注入自然也没触发。
**那条结论是错的**，正确的说法是：Auto 在本机一直选 AMF，因为它是第一候选且能打开。

### 9.3 顺带查清的一个事实：Auto 模式下 NVENC 本来就打不开

第二行显示 `h264_nvenc: avcodec_open2(enc): -2 (No such file or directory)`——这是**真实的**打开失败，不是注入。
原因是 Auto 用默认适配器（本机是 AMD 780M）建设备，NVENC 拿不到 NVIDIA 设备背后的纹理，于是失败。
这也解释了 V2.2 之前所有"Auto 导出都是 AMF"的现象：不是 AMF 抢了，而是 NVENC 在这个设备上没有可用路径。
Manual NVIDIA 之所以能用 NVENC，是因为它把设备建在 NVIDIA 卡上。

### 9.4 回退循环的真实证据

`Auto + amf 注入失败` 那一次是完整链条：**候选 1 注入失败 → 候选 2 被真正尝试并真实失败(-2) → 候选 3 真实失败 → 候选 4 成功**。
拒绝列表逐条记录了这三步，这是"失败后继续下一个候选"的直接证据。

"NVENC 失败后 AMF 成功"这个具体序列**在本机不存在**，因为 AMF 排在 NVENC 之前；
为了跑出它而伪造一个候选顺序，只会证明一个生产环境永远不会走的路径，所以本轮**没有**添加这种测试。
`auto_keeps_the_historical_order_untouched` 这条单测把真实顺序钉住，正是它让这次审计能立刻发现报告写错。
