## 2. 审计结论（本机实测代码路径）

| 问题 | 答案 |
|---|---|
| `clickRipple` 的真实数据流 | `sceneDescription.ts` → `scene.rs SceneCursor.click_ripple` → `plan_cursor` → `CursorPlan.ripples` → 三后端绘制 |
| 与 `clickBounce` 的关系 | 目前**由它派生**：`clickBounce > 0` 才下发 `clickRipple`，所以环没有独立开关 |
| `impacts` 与 `ripples` 是否重复 | **不重复**。`impacts` 是 mode 16，只在 3D 模型光标（`model3d`）且 `clickBounce>0` 时生成；`ripples` 是 mode 4，与 3D 无关。两者都在光标之下，先后绘制 |
| 现有轨迹怎么画 | `CursorPlan.taps`：同一束光标 sprite 按 `prev_placement → placement` 插值多次绘制（运动模糊式拖尾），不是独立轨迹层 |
| 三平台是否一致 | 是：都读同一个 `CursorPlan`，`ripples` 串进既有的 impacts 绘制循环（`draw_solid` / `make_bind`），没有第二套几何 |
| 场景参数怎么进原生 | `sceneDescription.ts` 组 JSON → `compositor_view.node` 的 `set_scene` → `Scene::from_json` |
| 哪些参数实时预览 | 所有 `SceneCursor` 字段（预览与导出走同一份场景），但 UI 上只有「点击弹跳」一个旋钮能影响环 |
| 哪些需要持久化 | 环的开关、每键开关、颜色、大小、透明度、时长——**目前都写死在 `sceneDescription.ts`**（72 px / 450 ms / 0.55），没有工程字段 |

结论：渲染链路是通的，缺的是**参数来源**（UI + 工程持久化）。

## 5. 真实视觉证据（本轮核心）

上一轮的失败条件是：点击落在画面最底边、背景是橙色壁纸、帧间页面还在变，无法把环单独指认出来。
本轮换成**静止画面 + 中央点击**，把变量消掉。

素材与工程（都不入库，位于 `%TEMP%\os-v272\`）：

```
still.mp4        1920×1080 / 30 fps / 4 s，纯 #202020 静止画面（随包 ffmpeg libopenh264 生成）
still.mp4.cursor.json  v3，光标停在 (0.5, 0.5)
                  t=1000 ms  click         （左）
                  t=2000 ms  right-click   （右）
                  t=3000 ms  middle-click  （中）
still.openscreen  由既有 15 s 工程改路径而来，清空 zoom/trim/speed/annotation
```

导出：`export still.openscreen -o out.mp4 --codec h264 --quality source` → 240 帧、4 s、465,084 B。

抽帧（`ffmpeg -ss`，裁中心 600×600）：

| 帧 | 观察 |
|---|---|
| `t=0.50`（对照） | 只有光标，无环 |
| `t=1.05`（左键后 50 ms） | 光标尖端有小环 |
| `t=1.30`（左键后 300 ms） | 环张开、变淡，白/灰色，直径约 40–50 px |
| `t=2.05`（右键后 50 ms） | **橙色**环（与左键明显不同） |
| `t=3.05`（中键后 50 ms） | 按设计应为蓝色（未逐张目检，见下） |

这是真实 `compositor_view.node`（`0891de76…`）渲染的导出帧，不是单元测试、不是 mock。

## 10. 负向验证

- `t=0.50` 对照帧没有环 → 环不是常驻涂层。
- 左键（白）与右键（橙）在同一位置、同一时长下颜色不同 → 不是同一效果被复用。
- 上一轮「帧字节不同但看不出环」的结论被本轮推翻：换静止背景后环可被单独指认——**那之前的 PARTIAL 是因为观测条件，不是因为没渲染**。
